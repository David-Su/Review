# 一元App
## 帖子编辑模块
### 页面结构
ViewPager2嵌套两个Fragment（富文本+图文）。
### 插入图片
图片上传后，并将图片作为ImageSpan（ImageSpan需要一个Drawable和source，source使用上传后的Url，以便后续解析富文本的图片可以用）插入到EditText中（EditText可以插入富文本）。
### 删除图片
监听EditText的键盘事件，在删除的事件中，找到游标所在的行中的ImageSpan并删除。  
这里有一个坑，如果ImageSpan在行首的位置，直接删除ImageSpan，所在行会留下一篇空白的空间，应该是EditText的一个Bug。解决方式是删除ImageSpan之后把当前行的行首的换行符给删除掉再插入回去。
### 保存草稿
通过Room分别保存内容和投票数据。查询的时候通过@Embedded一起查询出来（通过@Relation将内容的Id与投票数据的Id联合起来）。
## 帖子编辑论坛搜索模块
### 加载列表数据
由于服务端不允许一次加载所有数据，所以是在一个suspend方法内开启一个循环每页加载并根据拼音首字母分类。
### 右侧字母索引
是一个RecyclerView。
### 触摸实现
对其设置一个onTouchListener，在onTouch中先通过RecyclerView获取当前所有的ViewHolder，再遍历这些ViewHolder，获取其中的View，通过这个View的top和bottom判断触摸的位置是否在其范围内，如果是，则修改这个ViewHolder对应的数据状态，刷新列表。
### 列表同步滑动实现
找到高亮字母在Items中的位置，通过layoutManager滑动到该位置。
## 应用内全局消息推行
同意Kotlin的Channel构建一个的全局通知控制器。
### 发送
通过Channel.send发送到控制器。
### 接收
控制器开启循环，不断从Channel接收通知数据，获取到通知数据之后，拿到最顶层的Activity的WM构建一个类似横幅的子Window。
### 移除通知
由于通知会显示一段时间，所以我会用delay函数挂起一段时间再通过WM移除，这个delay我会用launch包起来，launch会返回一个Job，我会保存这个Job，并且使用Job.join()挂起，取消的时候只要cancel这个Job就好。
## 下载悬浮球
### 悬浮球服务封装
悬浮球显示的具体逻辑封装在一个服务，服务开启时添加悬浮球窗口，服务关闭时移除悬浮球窗口。下载开始和接收都有对应的广播，从广播接收器处开关服务。
### 下载悬浮球的滑动
* 根处理重写onInterceptTouchEvent，如果是move事件则拦截，后续事件都会给根节点处理。当然自身的onTouchEvent也要返回true，防止没有子节点处理down事件
* 在onTouchEvent处理move事件时，通过计算当前move事件滑动的距离（跟down事件记录的点位做对比）计算出悬浮球的Window.LayoutParams并通过updateViewLayout更新悬浮球位置
* 在onTouchEvent处理up事件时，要矫正悬浮球的位置，使得它的y不可以超出屏幕，x根据当前位置调整到最左或最右形成吸附效果。
### 悬浮球关闭
关闭区域同样也是一个Window设置在屏幕的最下方，在onTouchEvent处理up事件时，如果悬浮球在屏幕上的位置与关闭区域在屏幕上的位置有重合则直接关闭服务。
### 与同事的协调
悬浮球里面的内容显示是同事负责写的，在悬浮球的根部局中我会声明一个自定义View，这个View的代码由他负责。他需要通过接口通知我用户点击了下载完成提示框的关闭按钮，我这边接着把整个悬浮球服务关闭。
### 动态监控球体大小变化
为了保持解耦性，悬浮球的绘制逻辑对我这边是封闭的，所以悬浮球大小变化是不会直接通知到我这边的。因此我使用GlobalLayoutListener对球体做了一个重绘的监控，当这一次重绘跟上一次重绘的大小不一时，我会调整其位置使之不会超过屏幕。
## 我的模块
我的群聊和我的游戏是类似的列表，所有抽取了一个Base Adapter。
* BaseAdapter的子类有我的游戏Adapter，我的群聊Adapter。都需要传入两个List，一个是主要Item列表，另一个是次要Item列表
* BaseAdapter用枚举列出所有Item类型，如主要item、次要item、主要item数量为空提示、更多次要item等等。BaseAdapter会通过两个List决定ItemCount，ItemType
* 子类只需要重写onBindViewHolder和另外一个protected的方法，方法参数是我定义的枚举，返回值是ViewHolder，这个方法是BaseAdapter暴露给子类的，调用处是基类中onCreateViewHolder。因为我希望子类只需要关注我定义的枚举类型就可以了。

这样子就把两个RecyclerView的共同逻辑抽取到了Base中，而子类只需要关注自身的UI绘制细节就可以。

## 模块化
SDK中存在很多功能模块，如连点器、如果都放在同一个module的话，代码耦合度比较高，而且也不好维护。所以将每个独立的功能都进行模块化处理。
### 模块的初始化
每个模块会声明同一个Provider，并且在meta-data中声明一个本模块的启动器（全限定类名）：
```xml
 <provider
     android:name="com.anjiu.repository.bridge.initializer.SdkInitializationProvider"
     android:authorities="${applicationId}.sdk-initializer"
     android:exported="false">
     <meta-data
         android:name="com.anjiu.toolkit.channel_tools.initializer.ChannelToolsInitializer"
         android:value="" />
 </provider>
```
由于各个模块声明的是同一个provider，所以打包的时候清单会把这些provider标签合并成一个。当这些provider启动时，会通过反射构建meta-data的启动器。  
### 模块间交流
所有模块都会依赖一个common模块，common中有一个事件中转站。中转站的功能就是注册监听和发送事件，一般模块在初始化的时候会向中转站注册一个监听，监听各类其他模块的事件，也会向中转站发送事件给其他模块。以此进行模块间的通信。

### 小窗模式
1. 通过游戏Activity的根View找到游戏视图，通常是一个SurfaceView，也有可能是一个WebView或者com.netease.NeoXView
2. 给SurfaceView设置一个固定宽高（SurfaceView的SurfaceHolder可以设置一个宽高）
3. 将游戏视图从游戏Activity中移除，以下两个步骤的目的是欺骗GLSurfaceView，让它在原始图onDetached和在新视图onAttached的时候并不会重新加载。  
游戏视图一般是：GLSurfaceView、SurfaceView、WebView
    1. hook GLSurfaceView的onDetachedFromWindow方法，在mDetached方法执行前把mGLThread把mGLThread设置为空并保存起来（防止mGLThread.requestExitAndWait退出线程）。
    2. 在mDetached方法执行后把mGLThread重新赋值为原来的值，并将mDetached设置为false（防止重建GLThread）
    ```java
    @Override
    protected void onAttachedToWindow() {
        super.onAttachedToWindow();
        if (LOG_ATTACH_DETACH) {
            Log.d(TAG, "onAttachedToWindow reattach =" + mDetached);
        }
        if (mDetached && (mRenderer != null)) {
            int renderMode = RENDERMODE_CONTINUOUSLY;
            if (mGLThread != null) {
                renderMode = mGLThread.getRenderMode();
            }
            mGLThread = new GLThread(mThisWeakRef);
            if (renderMode != RENDERMODE_CONTINUOUSLY) {
                mGLThread.setRenderMode(renderMode);
            }
            mGLThread.start();
        }
        mDetached = false;
    }

    @Override
    protected void onDetachedFromWindow() {
        if (LOG_ATTACH_DETACH) {
            Log.d(TAG, "onDetachedFromWindow");
        }
        if (mGLThread != null) {
            mGLThread.requestExitAndWait();
        }
        mDetached = true;
        super.onDetachedFromWindow();
    }
    ```
4. 暂停游戏视图。通过反射手动调用游戏视图的暂停方法，根据不同类型的视图有不同的方法，一般是onPause
5. 通过父节点的removeView移除游戏视图
6. 把游戏视图用一个控制界面ViewGroup包一下通过WM的addView添加一个窗体
7. 恢复游戏视图。根据不同的游戏视图调用其恢复方法，一般就是叫onResume
### 连点器
#### 连点
##### 添加触点（点击仪表盘上的添加）
获取Activity的ContentView，通过addView的方式将触点布局添加到ContentView上。通过Translate设置触点的初始位置。
#### 触点的移动
在触点View的onTouchEvent中处理事件，在Move事件中设置Translate移动。
#### 保存方案
把触点在屏幕上的位置上报给服务端。
#### 执行连点
获取触点在ContentView上的位置，将位置封装成一个Down事件和一个Up事件，再通过Activity的DecorView的dispatchTouchEvent分发出去
### 录制
#### 开始录制（用户在屏幕上绘制路径）
1. 给ContentView添加一个全屏透明的自定义View
2. 通过给Activity的Window设置一个Callback获取触摸事件（Callback中可以重写dispatchTouchEvent），在dispatchTouchEvent记录用户的操作轨迹，比如说点击的位置、移动的路径位置、抬起的位置
3. 通过这些记录数据在onDraw的时候通过Canvas的drawPath（绘制路径）、drawBitmap（绘制触点）等绘制方式绘制完整路径
#### 执行连点
通过DecorView的dispatchTouchEvent把时间分发出去

# 转包脚本
## 主流程
1. 反编译游戏APK，得到一个输出目录
2. 反编译一个Demo Apk（集成了SDK的一个App的Apk），得到一个输出目录
3. 替换游戏的SDK代码
    1. 在游戏输出目录中的smali目录中移除SDK的代码，通常是整个包移除掉，比如我们的SDK包目录就是com/game/sdk、com/yaoyue/release
    2. 把Demo输出目录中的SDK相关的smali代码拷贝到游戏输出目录的smali目录中
4. 解压SDK的aar文件（aar本质是一个zip文件）,得到一个输出目录
5. 属性合并（游戏输出目录和aar输出目录都有values文件夹）
    1. 遍历游戏和SDK的同名values文件夹
    2. 遇到同名的xml文件，将SDK中的属性迁移到游戏的Xml目录（同名覆盖，不同名新增）
    3. 剩下的SDK中存在但是游戏中不存在的Xml，则直接迁移到游戏的Values目录中。前提是已经删除这个Xml已经删除掉游戏Values目录下的的所有Xml中重名的属性
