## 进程和线程的区别
### 定义层面
* 进程  
是一个正在运行的应用或程序的实例，拥有独立的内存空间和系统资源（文件句柄、网络端口等）。
在 Android 中，每个应用默认运行在独立的 Linux 进程里。
* 线程  
是进程内部的执行单元，共享该进程的内存和资源。
### 资源与隔离
* 进程  
不同进程之间的数据默认不可直接访问（需通过 Binder/IPC 交互）。   
拥有独立的虚拟机（ART/Dalvik）实例和垃圾回收器。
* 线程  
共享进程内的内存（堆、静态变量、对象等）。  
### 生命周期
* 进程  
由系统创建或因内存不足被系统杀死。
* 线程  
由进程创建和管理。进程被杀时，所有进程内的线程都会终止。
## 为什么基本重写equals方法时也需要重写hashCode方法。
首先明确两点：
* hashCode相同不能代表是同一个对象
* hashCode不同一定表示不同对象
而在一些基于哈希算法的集合中，如HashSet，通过哈希算法求出来的值不一样就代表两个元素，但此时这两个元素通过equals对比可能是相同的，应该认为是同一个元素。因此，需要重写hashCode方法，可以模仿equals基于字段生成一个hashCode，如：
```java
@Override  
public int hashCode() {  
    return Objects.hash(name, age);  
}  
```

## HashMap哈希冲突时，不同的插入方法区别
当插入的Key经过运算后会得到哈希桶的位置，当这个桶上本来就存在元素的时候就会哈希冲突，对于不同版本的HashMap会有不同的插入方法。
### Java7-头插法
Entry会插入到链表的头部，其他元素后移。  
#### 优点
  * 新插入的元素可以更优先访问到。
#### 缺点
  * 多线程同时插入时，可能会形成循环链表。  
  例子：  
  线程A、B都进行插入操作，并且都触发了扩容。双方扩容的逻辑都是将Entry1，Entry2都插入到某个桶上。假设线程A已经完成了链表的组装形成Entry2->Entry1的结构，但是此时线程B还停留在拿到Entry1并且将Entry1指向桶的第一位这一步，此时第一位时Entry2头部，所以形成了一个回环Entry2->Entry1->Entry2。  
  这个错误会查找操作进入一个死循环。
### Java8-尾插法
Entry会插入到链表的尾部。
#### 优点
  * 解决了死循环问题。
#### 缺点  
  * 新插入的元素没那么快被访问到。

## SharePreference原理
### 获取SharePreference对象
通过名字获取shared_prefs文件夹下对应的xml文件的SharePreferenceImpl对象并返回。SharePreferenceImpl初始化时会读取xml文件下的所有数据保存到内存中（一个Map类型的成员变量）。
### 读写
#### 1. 获取Editor对象保存操作  
Editor中有一个Map保存写入操作。
#### 2. 提交写入操作  
##### 通过apply提交
1. 将Editor保存的操作写入到内存中，即写入到SharePreferenceImpl的Map中。
2. 将一个countDown数量为1的CountDownLatch的await操作封装成Runnable并通过QueuedWork.addFinisher保存起来。
3.  通过QueuedWork执行将内存中的数据写入到文件中（同步），QueuedWork内部维护着一个HandlerThread，这个操作会在HandlerThread中执行。
##### 通过commit提交
与apply的不同之处在于第三步不会通过QueuedWork执行，而是在当前线程直接执行。
### 为什么SharePreference会导致ANR
在handlePauseActivity中，调用QueuedWork.waitToFinish()，这个方法会先在主线程直接执行QueueWork中还未执行的写入任务，然后执行所有addFinisher中添加的Runnable，也就是CountDownLatch的await操作（等待正在执行的写入任务）。如果QueueWork还未执行的任务比较多或者正在执行的任务耗时太长就会导致ANR。

## Handler的同步屏障
Handler的一个机制，没有开放给开发者，通过MessageQueue中的postSyncBarrier给消息队列发送一个屏障，这个屏障本质是一个没有target的Handler，之后MessageQueue执行到这个屏障的时候会优先处理他之后的异步Message，直到屏障被移除。
例如：requestLayout开始时会设置一个同步屏障并且等待屏幕刷新的回调，等到屏幕刷新的回调执行的时候会通过Handler发送一个异步消息去执行View的渲染流程并且移除这个屏障。
### 原理
当Looper通过MessageQueue获取下一个Message的时候，如果这个Message是个同步屏障Message，则会查询这个Message之后的一个异步Message并返回。不管找没找到，只要这个同步屏障还在，就只会执行异步Message，所以同步屏障用完之后需要移除。

## IdleHandler的作用
IdleHandler可以在消息队列没有Message需要处理或者下一个处理的消息还未到执行时间的时候得到一个回调，可以做一些优先级不高的任务。

## Serializable和Parcelable的区别
Serializable是Java自带的序列化方式，开发者只需要继承Serializable。传输的方式是先通过反射获取类的信息并序列化成Java标准的二进制格式并生成流，然后系统将流的数据传输到目标进程，目标进程再通过流反序列化。  
Parcelable是安卓独有的跨进程通信方式，开发者需要手动实现序列化与反序列化方法。传输的方式是先把数据写入Parcel，系统再将Parcel内部的流流的数据传输到目标进程，目标进程再通过Parcel恢复。  
Parcel针对安卓进行优化而且不涉及到Serializable中的反射，理论上来说高效一点。

## Fragment懒加载相关
### Fragment add生命周期变化
只要Fragment通过add被加载进容器了，则onAttach-onCreate-onCreateView-onViewCreated-onStart-onResume。
### Fragment hide show生命周期变化
当Fragment通过add被加载进容器了，hide、show任何生命周期都不会走，只在Fragment可见性发生变化的时候回调onHiddenChanged（如果可见性没生变化，则onHiddenChanged不会回调，比如说对本身就是可见的Fragment调用show）

当Fragment通过add被加载进容器了，则onPause-onStop-onDestroyView。
### Fragment replace生命周期变化
相当于先remove掉容器中所有的Fragment，再add一个Fragment（前提是这个Fragment没有被add过，否则报错）。
### 懒加载的方案
* 使用Androidx的ViewPager并在构造传入BEHAVIOR_RESUME_ONLY_CURRENT_FRAGMENT这个behavior。
* 使用ViewPager2。
* 使用show、hide的基础上使用FragmentManager.setMaxLifecycle。
 
以上方式都是利用了setMaxLifecycle这个方法，它可以限制某个Fragment当前最大的生命周期。  
比如说当某个Fragment可见时，设置它的最大生命周期为resume，其他的则为start（如果其他Fragment的状态为resume，降级为start会同时触发它的onPause）。那可见的Fragment就会走到onResume，其他不可见的Fragment只会走到onStart。

## LifeCycle的原理
一般来说我们写的Activity会继承ComponentActivity，ComponentActivity是一个LifeCycleOwner，也就是说他会持有一个LifeCycle。ComponentActivity在onCreate的时候会注入一个ReportFragment，这个ReportFragment是用来监听Activity的生命周期的，因为Fragment的很多生命周期是跟Activity同步的。在生命周期方法回调的时候ReportFragment会拿到ComponentActivity的LifeCycle（通过LifeCycleOwner的方法）并将事件分发给LifeCycle，LifeCycle又会分发给已经注册过的监听器。
## LiveData原理
### 监听
通过LiveData注册监听的时候需要传入一个LifeCycleOwner和一个数据观察者，LiveData会从LifeCycleOwner取出LifeCycle并添加一个观察者的包装类，这个包装类会包装着开发者传入的观察者。这个包装类有以下作用：
* 监听生命周期，当LiveData状态变为Destory的时候移除内部的观察者。
* 在LifeCycle在不活跃状态转为活跃状态的时候，将数据发送给内部的观察者。
### setValue
通过成员变量保存这个Value，如果LifeCycle活跃的话直接发送给观察者，如果不活跃会等到LifeCycle活跃时再发。
### postValue
通过Handler切换到主线程setValue。

## ViewModel为什么在旋转屏幕后不会丢失状态
首先，ComponentActivity是一个ViewModelStoreOwner，ViewModelStoreOwner可以提供一个ViewModelStore，ViewModelStore会存储跟这个ComponentActivity相关的ViewModel。当屏幕旋转时，Activity会触发onRetainNonConfigurationInstance并将ViewModelStore保存起来，等下次使用相同的ViewModel的时候会通过getLastNonConfigurationInstance把ViewModelStore取出来，再从里面取出对应的ViewModel。

## ViewModel什么时候调用onCleared
ComponentActivity会在onDestory的时候对ViewModelStore中的ViewModel执行clear。

## onRetainNonConfigurationInstance和getLastNonConfigurationInstance的作用
在屏幕旋转或者配置发生改变时，Activity会回调onRetainNonConfigurationInstance，这个方法接受一个Object作为返回值，开发者可以返回一个对象交由系统保存起来，后续可以通过getLastNonConfigurationInstance再取出来。要注意这个方法是将数据保存到应用进程，如果应用进程被系统重建的话数据也会丢失。

## setFactory和setFactory2有什么区别？
* 都是LayoutInflator通过XML标签创建View对象的一个接口
* setFactory是一开始就有的，setFactory2再Api11之后才有
* setFactory2比setFactory多了一个parent参数，可以知道当前节点的父节点。AppcompatActivity会在super.onCreate之前调用setFactory2传入一个Factory2用于构建AppCompat相关的View  
```java
    public interface Factory {
        /**
         * Hook you can supply that is called when inflating from a LayoutInflater.
         * You can use this to customize the tag names available in your XML
         * layout files.
         *
         * <p>
         * Note that it is good practice to prefix these custom names with your
         * package (i.e., com.coolcompany.apps) to avoid conflicts with system
         * names.
         *
         * @param name Tag name to be inflated.
         * @param context The context the view is being created in.
         * @param attrs Inflation attributes as specified in XML file.
         *
         * @return View Newly created view. Return null for the default
         *         behavior.
         */
        @Nullable
        View onCreateView(@NonNull String name, @NonNull Context context,
                @NonNull AttributeSet attrs);
    }

    public interface Factory2 extends Factory {
        /**
         * Version of {@link #onCreateView(String, Context, AttributeSet)}
         * that also supplies the parent that the view created view will be
         * placed in.
         *
         * @param parent The parent that the created view will be placed
         * in; <em>note that this may be null</em>.
         * @param name Tag name to be inflated.
         * @param context The context the view is being created in.
         * @param attrs Inflation attributes as specified in XML file.
         *
         * @return View Newly created view. Return null for the default
         *         behavior.
         */
        @Nullable
        View onCreateView(@Nullable View parent, @NonNull String name,
                @NonNull Context context, @NonNull AttributeSet attrs);
    }
```
